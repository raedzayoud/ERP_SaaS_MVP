## 3. Angular CLI Commands

Use Angular CLI to generate components and other Angular files.

### Create a project

Only if an Angular project does not already exist:

```bash
ng new erp-frontend --routing --style=css
cd erp-frontend
```

### Start the application

```bash
ng serve --open
```

### Generate components

```bash
ng g c features/auth/pages/login
ng g c layout/navbar
ng g c layout/sidebar
ng g c layout/main-layout
ng g c features/dashboard/pages/dashboard-home
ng g c features/crm/pages/contacts
ng g c features/products/pages/product-list
ng g c features/sales/pages/invoice-list
```

### Generate services

```bash
ng g s core/services/auth
ng g s features/crm/services/contact
ng g s features/products/services/product
ng g s features/sales/services/invoice
```

### Generate interfaces

```bash
ng g interface features/crm/models/contact
ng g interface features/products/models/product
ng g interface features/sales/models/invoice
```

### Generate guards and interceptors

```bash
ng g guard core/guards/auth
ng g interceptor core/interceptors/auth
```

Use these commands only when the corresponding files are needed. Check the installed Angular CLI version if a command or option differs.

### Build the application

```bash
ng build
```

## 5. Folder Organization Rules

- Use `core/` for application-wide services, guards, and HTTP interceptors.
- Use `layout/` for the sidebar, navbar, and main application layout.
- Use `shared/` for reusable components, common models, and pipes.
- Use `features/` to organize ERP business modules.
- Each feature may contain `pages/`, `components/`, `services/`, and `models/` when needed.
- `pages/` contains complete screens, such as Contacts or Invoices.
- `components/` contains smaller UI elements used by a feature.
- `services/` contains API calls and related service logic.
- `models/` contains TypeScript interfaces for the feature's data.
- Keep feature-specific code inside its feature folder.
- Move code into `shared/` only when it is genuinely reused.
- Do not duplicate services, models, or components.
- Do not create empty folders or unnecessary files in advance.
- Do not create additional architecture layers unless the project requires them.
- Follow Angular CLI naming conventions.
- Always inspect the current folder structure before generating files.

## 6. Angular Components

- Use standalone components.
- Keep each component responsible for one small task.
- Separate component logic, HTML, and CSS into their respective files when supported by the project's conventions.
- Use clear variable and function names.
- Keep HTML templates readable.
- Avoid putting API calls directly inside components.
- Avoid complicated component communication.
- Reuse components when doing so makes the code simpler.
- Do not create a reusable component for something used only once unless there is a clear benefit.

Example component:

```typescript

  standalone: true,
  templateUrl: './welcome.html',
  styleUrl: './welcome.css',
})
export class WelcomeComponent {

  showMessage(): void {
    console.log(this.message);
  }
}
```

This is an illustrative example. Follow the filenames and metadata generated by the installed Angular CLI.

## 10. Services and Backend Communication

Use services to communicate with the Spring Boot REST API.

Example:

```typescript
import { inject, Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

export interface Contact {
  id: number;
  name: string;
  email: string;
}

@Injectable({
  providedIn: 'root',
})
export class ContactService {
  private readonly http = inject(HttpClient);

  getContacts(): Observable<Contact[]> {
    return this.http.get<Contact[]>('/api/v1/contacts');
  }
}
```

The endpoint is an example only. Inspect the backend before using it.

Rules:

- Keep API requests inside services.
- Use the actual backend endpoints.
- Do not invent endpoints or response fields.
- Use environment configuration for the API URL.
- Handle API errors simply and clearly.
- Do not duplicate API requests unnecessarily.
- Use the existing HTTP configuration.
- Do not install additional libraries without permission.
